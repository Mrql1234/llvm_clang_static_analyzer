# 增强需求：可能除以零检测 (PossibleDivideZero)

**Workspace**: `csa-defect-checkers`
**Created**: 2026-03-17
**Status**: Draft
**基线**: MVP 已完成 `core.DivideZero` 验证（仅报"必定除零"）

---

## 1. 问题描述

当前 CSA 的 `core.DivideZero` 采用"必定缺陷"策略：只有在路径分析能证明除数**一定为零**时才报警。对于以下场景不会报告：

```cpp
int divisor = get_value();  // 外部输入，未知值
int result = 100 / divisor; // 不报 — 除数"可能"为零但无法证明"一定"为零
```

在安全关键领域（航空、汽车、医疗、MISRA/CERT 规范），要求更严格：**除法前必须证明除数非零**，否则视为缺陷。

### CSA 内部判断逻辑

```
SVal Denom = C.getSVal(B->getRHS());
auto [stateNotZero, stateZero] = CM.assumeDual(State, *DV);

if (!stateNotZero)        → 除数必定为零 → core.DivideZero 报警 ✅
if (stateNotZero && stateZero) → 除数可能为零也可能非零 → 不报 ❌ ← 增强点
if (!stateZero)           → 除数必定非零 → 安全，不报 ✅
```

## 2. 推荐方案：新建 `alpha.core.PossibleDivideZero` CSA Checker

### 设计原则

- **不修改**已有 `core.DivideZero`，避免给通用场景引入误报
- 新建独立 Checker，以 `alpha.` 前缀注册，表示实验性/可选
- 用户通过 `-analyzer-checker=alpha.core.PossibleDivideZero` 显式启用
- 与 `core.DivideZero` 互补：一个报"必定"，一个报"可能"

### 架构定位

| 层级 | Checker | 策略 | 适用场景 |
|------|---------|------|---------|
| 必定缺陷 | `core.DivideZero` (已有) | `!stateNotZero` 才报 | 通用软件 |
| 可能缺陷 | `alpha.core.PossibleDivideZero` (新建) | `stateZero` 可行即报 | 安全关键系统 |

### 技术方案

**继承模式**: `CheckerFamily<check::PreStmt<BinaryOperator>>`（与 `DivZeroChecker` 保持一致）

**核心逻辑**:

```
checkPreStmt(BinaryOperator *B, CheckerContext &C):
  1. 过滤非除法/取模运算
  2. 获取除数的 SVal
  3. assumeDual(state, denom):
     → (stateNotZero, stateZero)
  4. 判断条件（与现有 DivZeroChecker 的区别）:
     ┌──────────────────────────────┬─────────────────┬──────────────────────┐
     │ 条件                         │ DivZeroChecker  │ PossibleDivideZero   │
     ├──────────────────────────────┼─────────────────┼──────────────────────┤
     │ !stateNotZero && stateZero   │ 报 (必定为零)    │ 报 (必定为零)         │
     │ stateNotZero && stateZero    │ 仅报 tainted    │ 报 (可能为零) ← 关键  │
     │ stateNotZero && !stateZero   │ 不报            │ 不报                  │
     └──────────────────────────────┴─────────────────┴──────────────────────┘
  5. 报告级别: warning (非 error)
  6. 消息: "Division by a value that may be zero"
  7. 继续分析: C.addTransition(stateNotZero) — 沿非零路径继续
```

**关键 API 调用**:

```cpp
ConstraintManager &CM = C.getConstraintManager();
ProgramStateRef stateNotZero, stateZero;
std::tie(stateNotZero, stateZero) = CM.assumeDual(C.getState(), *DV);

if (stateNotZero && stateZero) {
    // 除数可能为零 — 报 "可能除零"
    reportBug("Division by a value that may be zero", stateZero, C);
}
// 沿非零路径继续分析
C.addTransition(stateNotZero);
```

### 注册位置

- `Checkers.td`: 在 `let ParentPackage = CoreAlpha in { ... }` 中添加
- 全名: `alpha.core.PossibleDivideZero`

```
def PossibleDivZeroChecker : Checker<"PossibleDivideZero">,
  HelpText<"Warn when the divisor may be zero (not proven non-zero)">,
  Documentation<HasDocumentation>;
```

## 3. 验收场景

### 场景 1: 外部输入除零（应报警）

```cpp
int divisor = get_value();
int result = 100 / divisor; // WARN: "Division by a value that may be zero"
```

### 场景 2: 必定除零（应报警）

```cpp
int x = 0;
int result = 100 / x;      // WARN: "Division by a value that may be zero"
```

> 注：此场景 `core.DivideZero` 也会报。两个 Checker 独立运行，不冲突。

### 场景 3: 已验证非零（不应报警）

```cpp
int divisor = get_value();
if (divisor != 0) {
    int result = 100 / divisor; // OK — 路径约束证明 divisor != 0
}
```

### 场景 4: 条件赋值后除法（应报警）

```cpp
int d = 0;
if (condition())
    d = get_value();
int r = 100 / d;            // WARN — d 在某些路径上仍为 0
```

### 场景 5: 字面量非零除数（不应报警）

```cpp
int r = 100 / 7;            // OK — 字面量 7 非零
```

---

## 4. 边界情况

- 除数为取模运算（`%`、`%=`）同样适用
- 浮点数除法：CSA 不对浮点符号化，浮点除零不在本 Checker 覆盖范围
- 指针类型用作除数的极端情况：不覆盖
- 与 `core.DivideZero` 同时启用时，同一个"必定除零"可能出现两条 warning（可接受，用户可选择性启用）

---

## 5. 误报控制

预期误报来源与控制措施：

| 误报来源 | 示例 | 控制措施 |
|---------|------|---------|
| 函数返回值恒正但 CSA 无法推导 | `100 / array.size()` | 无法自动消除，用户可添加 `#pragma` 或不启用此 Checker |
| 已在别处验证但分析器未跟踪到 | 外部函数校验后使用 | CSA 跨函数分析可缓解部分场景 |
| 循环计数器 | `for (int i=1; i<n; i++) { x/i; }` | CSA 路径分析通常能推导 i != 0 |

**总体误报预期**: 中等。因此以 `alpha.` 前缀注册，面向安全关键项目的用户自主选择启用。

## 6. 备选方案（参考）

### 备选 A: 基于 Taint 分析

将外部函数返回值标记为"受污染"，在除法点检查除数是否被污染且未经验证。

- 优点：精准 — 只对外部未验证值报警
- 缺点：需配置 taint 源和传播规则，实现复杂
- 状态：暂不采用，可作为后续精化方向

### 备选 B: clang-tidy AST 检查

纯 AST 层面检查每个除法的除数是否有前置 `!= 0` 判断。

- 优点：简单、可预测
- 缺点：不理解路径，无法区分"已在其他分支验证"的场景
- 状态：暂不采用
