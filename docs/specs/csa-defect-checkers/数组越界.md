# 增强需求：可能数组越界检测 (PossibleArrayBound)

**Workspace**: `csa-defect-checkers`
**Created**: 2026-03-17
**Status**: Draft
**基线**: MVP 已完成 `security.ArrayBound` 验证（仅报"必定越界"）

---

## 1. 问题描述

当前 CSA 的 `security.ArrayBound` 采用"必定缺陷"策略：只有在路径分析能证明数组下标**一定越界**时才报警。对于以下场景不会报告：

```cpp
int index = get_value();  // 外部输入，未知值
int arr[10];
arr[index] = 0;           // 不报 — 下标"可能"越界但无法证明"一定"越界
```

与除以零场景完全对称：

| 场景 | 代码 | 现有行为 | 原因 |
|------|------|---------|------|
| 确定越界 | `int i = -1; arr[i]` | ✅ 检出 | CSA 追踪到 index == -1，证明越界 |
| 确定越界 | `arr[15]`（数组大小 10） | ✅ 检出 | 字面量 15 > 9，证明越界 |
| 可能越界 | `int i = get_value(); arr[i]` | ❌ 不报 | 未约束符号值，无法证明一定越界 |

### CSA 内部判断逻辑（ArrayBoundChecker 简化）

```
performCheck(Expr *E, CheckerContext &C):
  1. 获取访问的 MemRegion 和字节偏移 ByteOffset
  2. 获取区域的 Extent（总大小）
  3. assume(ByteOffset < 0):
     → 如果必定为负 → 报 "Out of bound access preceding array"
  4. assume(ByteOffset >= Extent):
     → 如果必定越上界 → 报 "Out of bound access after the end of array"
  5. 两者都不成立 → 安全，不报
  6. 关键：对未约束的符号值，assume 两个方向都可行 → 不报
```

## 2. 推荐方案：新建 `alpha.security.PossibleArrayBound` CSA Checker

### 设计原则

- **不修改**已有 `security.ArrayBound`，避免给通用场景引入误报
- 新建独立 Checker，以 `alpha.` 前缀注册
- 用户通过 `-analyzer-checker=alpha.security.PossibleArrayBound` 显式启用
- 与 `security.ArrayBound` 互补：一个报"必定越界"，一个报"可能越界"

### 架构定位

| 层级 | Checker | 策略 | 适用场景 |
|------|---------|------|---------|
| 必定缺陷 | `security.ArrayBound` (已有) | 只在证明必定越界时报 | 通用软件 |
| 可能缺陷 | `alpha.security.PossibleArrayBound` (新建) | 下标未证明在合法范围内即报 | 安全关键系统 |

### 技术方案

**继承模式**: `Checker<check::PostStmt<ArraySubscriptExpr>>`

**核心逻辑**:

```
checkPostStmt(ArraySubscriptExpr *ASE, CheckerContext &C):
  1. 获取数组基地址的 MemRegion
  2. 获取下标的 SVal
  3. 如果下标是 UndefinedVal 或无法获取 → 跳过
  4. 获取数组的已知大小 Extent（ElementCount）
  5. 检查下标合法性:

     a. 下界检查:
        assume(index >= 0):
          → stateNonNeg = 可行
          → stateNeg = 可行
          → 如果 stateNeg 可行（不管 stateNonNeg）→ 报"下标可能为负"

     b. 上界检查（如果 Extent 可知）:
        assume(index < Extent):
          → stateInBound = 可行
          → stateOutBound = 可行
          → 如果 stateOutBound 可行（不管 stateInBound）→ 报"下标可能超出数组上界"

  6. 如果两项检查都通过 → C.addTransition(constrainedState)
```

**与现有 ArrayBoundChecker 的区别**:

```
                    ArrayBoundChecker          PossibleArrayBound
检查位置            PostStmt (多种表达式)       PostStmt<ArraySubscriptExpr>
判断逻辑            只在证明必定越界时报         未证明必定合法时报
覆盖范围            数组下标/指针解引用/成员访问  仅数组下标访问（简化版）
报告级别            error                       warning
```

**简化策略**: 相比 `ArrayBoundChecker` 需要处理指针算术、成员访问、`UnaryOperator` 等复杂场景，`PossibleArrayBound` 只聚焦 `ArraySubscriptExpr`，降低实现复杂度。后续可逐步扩展。

**关键 API 调用**:

```cpp
const auto *ASE = cast<ArraySubscriptExpr>(E);
SVal IndexVal = C.getSVal(ASE->getIdx());

auto DV = IndexVal.getAs<DefinedSVal>();
if (!DV) return;

ProgramStateRef State = C.getState();
ConstraintManager &CM = C.getConstraintManager();

// 下界检查: index >= 0?
SValBuilder &SVB = C.getSValBuilder();
SVal Zero = SVB.makeZeroVal(ASE->getIdx()->getType());
SVal IsNeg = SVB.evalBinOp(State, BO_LT, *DV,
                           Zero.castAs<NonLoc>(),
                           SVB.getConditionType());
if (auto IsNegDef = IsNeg.getAs<DefinedSVal>()) {
    auto [stateNeg, stateNonNeg] = State->assume(*IsNegDef);
    if (stateNeg) {
        // 下标可能为负
        reportBug("Array index may be negative", C, ASE);
    }
}

// 上界检查: index < extent?
DefinedOrUnknownSVal Extent = getDynamicExtent(State, Region, SVB);
// ... 类似逻辑
```

### 注册位置

- `Checkers.td`: 在 `let ParentPackage = SecurityAlpha in { ... }` 中添加
- 全名: `alpha.security.PossibleArrayBound`

```

```

## 3. 验收场景

### 场景 1: 外部输入做下标（应报警）

```cpp
int index = get_value();
int arr[10];
arr[index] = 0;    // WARN: "Array index may be out of bounds"
```

### 场景 2: 确定负值下标（应报警）

```cpp
int index = -1;
int arr[10];
arr[index] = 0;    // WARN: "Array index may be negative"
```

> 注：此场景 `security.ArrayBound` 也会报。两个 Checker 独立。

### 场景 3: 已验证范围（不应报警）

```cpp
int index = get_value();
int arr[10];
if (index >= 0 && index < 10) {
    arr[index] = 0;  // OK — 路径约束证明 0 <= index < 10
}
```

### 场景 4: 部分验证（应报警）

```cpp
int index = get_value();
int arr[10];
if (index >= 0) {
    arr[index] = 0;  // WARN — 仅验证了下界，未验证上界
}
```

### 场景 5: 字面量合法下标（不应报警）

```cpp
int arr[10];
arr[5] = 0;        // OK — 字面量 5 在 [0, 9] 范围内
```

### 场景 6: 循环变量（取决于约束）

```cpp
int arr[10];
for (int i = 0; i < 10; i++) {
    arr[i] = 0;      // OK — CSA 追踪循环变量约束，通常能证明合法
}
```

## 4. 边界情况

- 多维数组：仅检查最外层下标（内层展开后等价于一维访问）
- 动态分配数组（`new int[n]`）：CSA 的 `getDynamicExtent` 可以追踪动态大小
- 指针算术（`*(p + i)`）：本 Checker 暂不覆盖，留给后续扩展
- 结构体成员数组：`obj.arr[i]` — `ArraySubscriptExpr` 可匹配，但 Extent 获取需要额外处理
- 零长度数组（柔性数组成员）：应跳过，避免对惯用写法误报

---

## 5. 误报控制

| 误报来源 | 示例 | 控制措施 |
|---------|------|---------|
| 函数内部保证返回合法范围但 CSA 不知 | `arr[clamp(x, 0, 9)]` | 用户可添加 `__builtin_assume()` 或不启用此 Checker |
| 循环变量边界条件复杂 | 嵌套循环下标 | CSA 路径展开通常能覆盖简单循环 |
| 枚举值做下标 | `arr[MY_ENUM_VALUE]` | 枚举通常有确定值，CSA 可推导 |

**总体误报预期**: 中等偏高（高于 PossibleDivideZero），因为数组访问更普遍。以 `alpha.` 前缀注册，用户自主选择。

## 6. 备选方案（参考）

### 备选 A: 基于 Taint 分析

标记外部输入为"受污染"，当污染值未经边界检查直接用作数组下标时报警。

- 优点：精准 — 只对外部未验证值报警
- 缺点：需配置 taint 源和传播规则
- 状态：暂不采用，可作为后续精化方向
- 注意：`security.ArrayBound` 已内置部分 taint 支持（`TaintBT`），可研究复用

### 备选 B: clang-tidy AST 检查

纯 AST 层面检查每个数组访问的下标是否有前置边界判断。

- 优点：简单、可预测
- 缺点：不理解路径，无法利用约束信息
- 状态：暂不采用
